# OCLive 是什么（5 分钟）

> 读完这一页你就知道：这是什么、给谁用、不是什么、下一步去哪。
> 想直接开工 → [2 分钟定位](#2-分钟你该去哪)。**最后更新**：2026-10-18。

---

## 一句话

**OCLive 是一套让 AI 角色"能装、能换零件、能离线跑"的内核。**

角色内容打包成**角色包**，像插件一样装上；决定角色怎么记事、怎么说话的部分是**可替换的零件**；整套东西跑在你自己机器上。

---

## 先说一个具体的

你装上一个叫"沐沐"的角色包 —— 一个有点嘴硬的小女孩。

她记得你上周说过喜欢草莓蛋糕。你心情不好时她语气会收敛。你三天没来，她对你的态度会淡一点。

**注意"记得"这两个字。**

它不是聊天记录里的搜索。她的记忆是另一套会**淡化、强化、分层**的东西，和聊天档案故意分开 —— 后面讲为什么。

---

## 为什么要做这个

做 AI 角色，通常得在两个东西之间选：

**用现成平台** —— 省事，但角色到底怎么记事、怎么接模型，你只能碰到露出来的那几层。
**自己从零搭** —— 什么都能改，但人设管理、记忆、对话循环、崩溃恢复全得自己写。

OCLive 想做第三条路：**零件是现成的，但你随时能换。**

- 人设打包成**角色包**，能分发、能装、能改
- 默认零件不满意就换 —— 觉得记忆太笨？换一套实现
- 数据留在你自己的硬盘上
- 想装到一块开发板上当摆件，也行 —— 同一个内核

所以它不是"又一个聊天界面"，更像**一套标准 + 一堆可替换的零件**，界面只是最外面那层壳。

## 四层

这是整个项目最核心的切法。用一组连续的比喻讲完。

### ① 内核 = 接口标准 + 安全规范

> 想象一张**接口清单**：USB-C、HDMI、3.5mm 音频、网口、电源口。
> 它规定**每个口什么形状、能传什么信号**；同时还有一份**安全规范**——不能超载、短路要断开、失败要报出来。

OCLive 的内核也是这两样：

- **形状**：六种能力端口各收什么、返回什么
- **底线**：失败怎么表达、错误怎么分类、哪些组合不合法——这些是**所有 Host 都必须遵守**的

它不规定角色长什么样、用什么模型、存在哪个库。

**泼一盆冷水**：它不是 USB-C 那种行业标准，**只是这个项目自己的一套约定**。但纪律是真的——改它要按"破坏性变更"走流程，因为有人在按它实现。

### ② 六槽 = 六种不同的接口

> USB-C 和 HDMI **不能互换**。接显示器就得用 HDMI 口。

六个槽是**六种不同种类的接口**，各管各的：

| 槽 | 接什么 | 大白话 |
|---|---|---|
| `memory` | 记什么、忘什么 | 她的记性 |
| `emotion` | 你的情绪信号 | 她判断你开不开心 |
| `event` | 发生了什么 | 她理解的"剧情推进" |
| `prompt` | 怎么把话说给模型听 | 她开口前的准备 |
| `llm` | 谁来生成回复 | 她的嘴 |
| `agent` | 能不能用工具 | 她的手（可选） |

**一个槽可以接多台设备** —— 像 USB 口接一个 **Hub**。所以"记忆"这一个口能同时挂好几套实现，由宿主决定怎么合用。

**六个都可选。** 只想聊天，只要 `prompt` + `llm`，其余设空也能跑。

### ③ Host = 一台具体整机

> 同一套接口标准，可以拧出一台笔记本、一台台式机、一台一体机。

Host 决定**怎么把这六个口接起来跑一轮对话**。它最重（参考 Host 约 7.4 万行），因为真实的坑全在这：并发、崩溃恢复、资源抢占、状态污染。

**但 Host 可替换。** 已有三个真实形态：

| 形态 | 是什么 | 规模 |
|---|---|---|
| **Chat Pro** | 桌面应用（主路径） | 本仓 |
| **VS Code 扩展** | 编辑器里陪聊 | 姊妹仓 |
| **枪娘器灵** | 装在玩具枪上的硬件角色 | **Host 只有 603 行** |

最后一行最能说明问题：**换到完全不同的领域，Host 可以只有 600 行。**

### ④ 发行版 = 同一个内核的不同"发行版"

> 同一个 Linux 内核，可以装成 Ubuntu、Debian、树莓派系统。

`distro` 这个词就是从 Linux 借的：**内核是同一个，发行版决定默认装什么、开什么、给谁用。**

OCLive 现在有三份：桌面版（主路径）、VS Code 版、AI 剧场版。

---

## 四件最容易混的事

### 记忆：不是一个数据库，是一套像人脑的机制

> 人脑的记忆不是"一个文件夹"。起码三件事一起工作：
> **刚说的话还热着**（短期）·**重要的事慢慢沉淀**（长期）·**不重要的自动淡掉**（遗忘）。
> 反复提到的会更牢（强化）。

OCLive 把这三件事做成可自由组合的实现，拼在同一个 `memory` 槽里。

**所以"删掉聊天记录"不等于"清空她的记忆"** —— 两套存储。你清掉档案，她的印象还在。

### 角色包 ≠ 蓝图

> 角色包是**演员的设定集**（长什么样、什么性格、说话方式）；
> 蓝图是**剧场的技术清单**（灯光音响怎么接、用哪家设备）。

| | 谁改 | 装什么 |
|---|---|---|
| 角色包 | 创作者 | 人设、场景、声音、立绘 |
| 蓝图 | 管理员 / 集成方 | 六个口各接谁、参数怎么配 |

**创作者改人设，不会误碰后端接线。**

### 关系和好感：是"阶段"，不是"分数"

> 你不会给邻居打 43 分。你只会觉得："不太熟""算认识了""是朋友了""关系很近了"。

关系是**离散的五个阶段**（陌生 → 熟人 → 朋友 → 密友 → 伴侣），好感值只是往下一阶段推进的动力，不是挂在脸上的数字。

### Event Ring：不是第七个槽

> 剧场后台的**广播系统**。它不做演出，只管三件事：
> 谁可以播报、谁听到了、谁有权因为这条广播开口说话。

模块可以往里报"发生了什么"，但**广播系统自己不产生剧情**。

## 是 / 不是

✅ 一家人可以自己装、自己换零件的 AI 角色运行时
✅ 角色内容的**可分发格式**（角色包）
✅ 数据默认留在你自己机器上

❌ 不是又一个 AI 聊天界面 —— 界面只是最外面那层壳
❌ 不是通用 Agent 框架 —— 六个口**为角色陪伴设计**，做客服或代码助手需自行扩展（允许的）
❌ 不是云端服务 —— 没有账号体系，不连中央服务器
