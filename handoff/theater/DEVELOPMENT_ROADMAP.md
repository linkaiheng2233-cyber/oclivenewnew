## 0. 这份文档是什么

把 AI 剧场发行版背后的**完整思路**一次录入，作为开发路线与对齐基准（交接给其它对话 / 协作者 / 未来的自己时，读这一份即可对齐）。

**一句话**：先把"早饭那一场、两个角色、几个戳点"做到让陌生人脱口"卧槽"，**其余一切都等这一声之后再说**。

## 1. 定位（OClive 是什么）

- **不是 agent，不是聊天软件，是一颗"灵魂内核"**：给模型穿一套机甲（记忆、情绪、性格成长、关系、可携带的身体），让模型**成为一个"某人"，而不只是完成任务**。
- **轴：being（是什么）而非 doing（做什么）**。Agent 是一只手；OClive 是整个存在，agent 只是其中一个器官。
- **对技术听众的一句定位**："AI 灵魂领域的 Cursor"——同一个母题（外壳放大底座模型），不同的轴（**构成存在，而非提升能力**）。
  - ⚠️ 措辞纪律：**不要说"提升模型能力"**（会被看穿，且挤进红海）；要说**"让模型成为某人"**。
- 一切可替换（记忆 / 情绪 / 性格 / 编排）、本地优先、隐私、角色包可跨发行版与载体携带。类比："AI 灵魂的 Linux + 创作工坊"。
- **AI 剧场是这颗内核的第一个"无法反驳"的化身**——因为"两个被用户定义灵魂的角色当场对戏"是聊天框在物理上做不出来的，一眼可见 being。

## 2. 战略处境与已定决策

- **内核不是护城河**（可被复刻，且我们开源、欢迎复刻）。护城河 = **生态 / 社区网络效应**、成为"可携带灵魂"的**事实标准**、**反锁定的信任**（在位者结构上无法可信占据）、**速度 + 品味 + 叙事**。
- **真正的敌人是默默无闻，不是竞争。** 大厂不会把一个"反锁定"的开放内核当产品做（与其锁定式变现冲突）；真正的风险是模型厂把"应用层"商品化——但那不是靠守内核能防的，是靠生态先扎根能防的。
- **因此：做出一个无法反驳的官方发行版**（它是矛、是 demo、是给 DeepSeek 的筹码，三位一体）。**官方发行版当明星打，不是当兜底养。不要等别人来写前端。**
- **许可证**：主仓 **Apache-2.0**（由 AGPL-3.0 切换；permissive，邀请商业下游；切换计划另见许可证 sweep 任务）。
- **DeepSeek**：是对的合作对象类型，但**先有引力再去敲门**（合作是 traction 的结果，不是替代）。作为模型后端接入**与许可证无关、随时可做**（OpenAI 兼容）。
- **零预算成本模型（穷学生友好，长期掏腰包 ≈ 0）**：
  1. **惊艳那一下**：强模型**一次性预生成**剧本骨架（几分钱，由作者跑，不是每用户跑）。
  2. **日常免费**：本地**千问 7B**（烧用户硬件，对作者 0 成本）+ 可选免费 / 极廉路由。
  3. **高质量 / 无限**：**BYOK**，用户自带 key（如 DeepSeek，对作者 0 成本）。
  - ⚠️ **绝不把所有用户路由到作者自己的一个免费 key**（违反 ToS、必被封）。自己的 key 只用于"一次性预生成"。

## 3. 三模式阶梯（总览）

作者权、AI 自主度、所需模型质量，三者**同步上升**。低地板、高天花板。

| 模式 | 用户做什么 | AI 做什么 | 模型需求 | 状态 |
|------|-----------|-----------|---------|------|
| **模式 1** | 在官方剧本上**微改动**（戳变量） | 只改动用户动的那一小段 | 本地 7B 即可 | **现在做** |
| **模式 2** | 写**剧本大纲** + 可导入角色包 | 围绕用户大纲**自行演绎** | 中 / BYOK | 冻结（roadmap） |
| **模式 3** | 提供**角色包**（自带场景与 prompt） | 基于角色包**自由演绎** | 强模型 | 冻结（roadmap，最后做） |

> **铁律**：模式 2 / 3 在模式 1 换到陌生人的"卧槽"**之前，一律不准开工**（见 §6）。

## 4. 模式 1 详细规格（这就是整个 v0）

### 4.1 场景
- **两个角色吃早饭、准备上学。**
- 场景足够日常、足够简单 → **变量本身就是分叉，无需写 if 线**。零认知负担，适合陌生人头 60 秒。
- 角色包与场景资产 **从 0 在本目录规划后** 再落入 `roles/`（旧 `theater-breakfast-*` 已清理）。

### 4.2 魔法的来源：两个"反差极大"的角色
- **舞台越简单，注意力越聚焦在角色反应上。卧槽 100% 住在这两个角色身上。**
- 反应平淡 / 雷同 = demo 当场死；反应**鲜明对撞** = 笑点、惊艳、想录下来发出去。
- 角色对照建议（择一打磨到发光）：焦虑负责型 + 懒散混乱型；或 面瘫隐忍 + 戏精。
- **几分钱强模型预算 + 最精的 prompt 手艺，全砸在这两个角色上。反差 = 喜剧 / 惊艳引擎。**

### 4.3 交互 = 淘气地"戳一戳"
- 用**一眼可见的可点芯片**让用户戳，把第一次微改的门槛降到零：
  - 🍵 让他们喝苦中药 · ⏰ 改到快迟到 · 🥦 逼吃讨厌的菜 · 😼 换个称呼 · 🎭 微调性格
- **小输入 → 肉眼可见的大后果**（出人意料又完全符合人设的反应）。机制上是小补丁，体感上要是大转折。
- **挑高含金量变量**（苦中药 / 迟到 / 讨厌的菜——逼出性格）**而非中性变量**（具体几点——改了看不出性格）。
- 把它框成**"调戏这两个人，看会怎样"**——最可分享、最可重复玩的交互模式（沙盒 / 模拟人生同理）。天生可剪、可传、玩不腻。

### 4.4 技术：预生成骨架 + 本地局部补丁（核心方法）
- **0:00 打开即活**：用**预生成好的开场**瞬间出字（零配置，打开两人已在吃、在拌嘴）。
- **用户的戳才调用本地千问**，且**只改动用户动的那一小段**（弱模型只干被严格约束的小活 → 质量与速度风险都塌下去）。
- **"弹改动加载"**把延迟变成有意的节拍（思考 / 加载动画遮住生成时间）。
- **补丁必须重锚到下一个固定节拍**：喂紧贴上下文（前后各一两句 + 严格语气 / 人设规格）+ 死框输出格式（"只改这个角色接下来 1–2 句，同语气，≤N 字，须自然导向下一固定节拍"），接不上就重生成。
- 这是混合生成方法（预生成强模型骨架 + 本地弱模型受限补丁 + 有界随机），是剧场的核心技术 IP。

### 4.5 零设置门槛
- **第一印象之前不许填任何 API key。** 预生成 + 本地模型扛住首启。
- API key 是后面"想深入 / 隐私 / 无限用"才出现的一步，不是入场券。**先爽，再让他配。**
- **模式 1 卡司**：首启默认 **mumu × 枫侵月**（零配置）；用户可在 **剧场设置 → 卡司** 导入/选择任意两个角色包并重开本场。**官方剧本大纲**（`breakfast.skeleton.json` beats/forks 锚点）固定不变，仅替换称呼与人设语气适配。
- **非默认卡司 AI 适配加载**：换角后前端 `adaptRuntimeSkeleton` → `POST /theater/scene` **`mode=cast_adapt`**（内核 `scene_director` 单次 LLM 改写开场 beats + 全部 fork 罐头文本；beat/fork id 与 `insertAfterBeatId` 不变）；结果缓存 `localStorage` `oclive.theater.adapted.v1`（key：`sceneId:castA.roleId:castB.roleId`）；**再次进入同组合命中缓存秒开**。`resolveCastTier`：**默认卡司**（mumu×枫侵月）= `default`（零 AI）；**任一侧偏离**即 `applied`（含**混合卡司**）。适配失败 / 超时 / 内核 offline → **`fallbackToDefaultCast`** 整局回官方默认，非换名半成品；设置 → **恢复默认卡司** 走 `applyDefaultCast`。

### 4.6 创作漏斗（通往编辑器的暗门）
- **"🎭 微调性格"这个戳点，本质是迷你版"创作"，是通往编辑器的暗门。**
- 用户戳性格戳上瘾时，**在欲望峰值**递一句：「✨ 想从头造一个完全属于你的灵魂？→」，接入已有的 `oclive-pack-editor`（**别重造编辑器**）。
- **先改后造（remix before create）**：别直接把人从"看剧场"丢进"完整编辑器"，先让他改爽一个现成角色。
- 邀请要**嵌在高潮里，不能埋在角落 / 菜单里**。

### 4.7 编辑器侧（为模式 1 的转化兜底，非首发重点）
- 零基础用户做的角色包要有**足够 prompt 约束以保证生成质量**——但实现方式是**反过来的**：
  - **别让新手写约束**；让工具**用模型把大白话变成严谨人设 prompt**（他输入"高冷剑客，话少但护短"，工具生成结构化严格 prompt）。
  - "会打字就能做"的真义 = **工具替他做 prompt 工程**。

### 4.8 验收 / 验证标准（模式 1 成功 = 模式 2/3 的验证门）
- **一个真实陌生人看了脱口"卧槽"，并追问"我能不能自己做一个？"。**
- 这句追问，才证明模式 2 / 3 值得建。**没有这句追问之前，模式 2 / 3 是空中楼阁。**

## 5. 模式 2 / 3（冻结，待解冻）

> 已设计、已记录，**未开工**。解冻条件 = 模式 1 通过 §4.8 验收门。

- **模式 2（用户大纲，AI 演绎）**：用户写剧本大纲 + 可导入角色包，AI 围绕大纲自行演绎；与模式 1 互补（模式 1 改既有剧本，模式 2 给骨架让 AI 填）。
- **模式 3（角色包自由演绎）**：用户提供角色包，AI 基于包内场景与 prompt 自由演绎。
  - ⚠️ **最贵最脆**：无固定节拍的自由对话 = "两个 AI 会聊崩"（绕圈 / 雷同 / OOC）的失败模式卷土重来，且**需强模型**（破零预算本地前提）。
  - **正因如此，它必须放最后**，等有真实用户（自带 key）或 DeepSeek 额度再做。**别让它的需求现在就渗进模式 1 的架构。**

## 5.5 产品与内核冻结（Theater v0）

在模式 1 通过 §4.8 **陌生人验收前**，**冻结**：

- 新增 `process_message` **编排阶段**
- 六槽扩展、蓝图 v3 DSL、`dual_core` / `expert_routing` 解冻
- **内核 / 后端模块 / 双核定制**（模式 3 范畴）

**允许**（不违反冻结）：

- theater 发行版打包、目录插件、UI 差分
- 模式 1 预生成骨架与局部补丁
- **场景导演（专用命令）**：`generate_theater_scene` / `POST /theater/scene`（`oclive_kernel_host::domain::theater::scene_director`）——一次 LLM 调用结构化重写整场 JSON beats；走 `AppState::llm` 与已配置模型，**非** `process_message` stage、**非**六槽
- **重演（混合 B，已 superseded）**：旧前端 `send_message`+正则局部补丁路径已由场景导演替代；保留 `buildWorkingScript` 作 fallback 罐头

**推迟到模式 3**：自由双角色来回、N cast 泛化、内核级双核编排与六槽后端模块定制。

**场景导演 UX（2026-06）**：

- 前端 `generate_theater_scene` **30s** 竞态超时；思考链播完后显示已等待秒数与模型阶段文案；invoke 失败必恢复 idle。
- 内核仅重写**涟漪区**（最后一项 tweak 插入点之后），前缀（含罐头 patch）原样拼接；默认 `max_beats=12`。
- 首轮 LLM 走 `generate_tag`（低 temperature）；内核单轮超时 `OCLIVE_THEATER_SCENE_TIMEOUT_SECS`（默认 **25**）；环境变量 `OCLIVE_THEATER_RIPPLE_MAX_BEATS`（默认 **12**）。

工程代理（如 `test:theater:smoke`）**不替代**真人「卧槽」门槛。

## 5.6 辅助小模型（草案 · 未实现）

> 解冻条件：涟漪重写 + 30s UX 上线后，慢模型 fallback 率仍高。

- **规则模板 + 小模型**：仅生成 3–5 行涟漪对白，失败率低于整场 JSON。
- **两阶段**：小模型草稿 → 可选大模型润色（用户有云端 key 时）。
- **环境开关**：预留 `OCLIVE_THEATER_AUX_MODEL`（本迭代不实现）。

## 6. 开发纪律（必须随这份路线一起遵守）

1. **只做模式 1。** 模式 2 / 3 在模式 1 拿到陌生人"卧槙"前不准开工。
2. **不做过早泛化**：别为了"将来好扩展模式 2/3"把模式 1 架构搞复杂——这正是内核里冻结掉的 speculative generality 纪律，别在发行版上重犯。
3. **别打磨引擎到完美才给人看**：先用手把这一场戏的**粗剪**做出来，**给 3 个陌生人看**，先验证那一声"卧槙"，再建批量生产它的引擎。
4. **官方发行版 = 明星 / 矛，不是兜底。**
5. **复用而非新建**：剧场复用 Chat Pro（`desktop`）的 `ToolShell` + `process_message`；profile 从本目录 [`theater.oclive.toml`](theater.oclive.toml) 模板接入后再差分；编辑器复用 `oclive-pack-editor`。
