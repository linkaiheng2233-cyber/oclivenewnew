## 为什么扩面，以及怎样控制维护量

维护者明确允许直接扩大实验范围，在实际使用中确认；因此不再把原八份样本上限当作继续使用的限制。[初始试点](WAVE-20261020-AI-DOCS-PILOT.md) 保留历史范围，当前命令与维护方式只在 [catalog README](../../catalog/README.md) 维护。

选用两种来源：原八份记录继续提供精选入口和一条限定摘要；其它入选原文由 Git 清单、标题与查询词现场派生入口，不另存卡片、摘要、审阅或版本锁。新增普通文档正常暂存／提交后即可被查询；修改正文也无需同步一份自动目录。

`query` 默认查询 `AGENTS.md`、根 `README.md`、`handoff/`、`creator-docs/`、`human-docs/` 的跟踪文档。路径含 `archive` 的目录及历史 `waves/` 排除；独立英文镜像、未跟踪笔记及其它工程文件不在本片发现范围内。正文可能仍含历史小节，工具不因此将整篇标为现行。

在父提交及本片编辑中的实际读取是 **413 份列入候选、146 份排除、267 份发现范围**；精选八份与发现文档有重合，不能相加为 275。早先临时盘点用 glob 漏了部分目录根文件，得到 395／249，已改以实际 Git 枚举为准。新增本历史报告后，排除数随正常暂存增加，精确冻结数由冻结后命令给出；文档量不是固定门禁。

Git 对象改为批量读取，避免每份文档各启动读取进程。没有搜索服务、持久缓存、额外依赖或自动写入；查询结果最多展示 20 个入口，每条正文引文最多 240 个 Unicode 字符。原文与 Git index 均只读。

## 实际使用：先定位，再读对应原文

以下均执行真实 CLI 查询，并回读命中章节及其必要上下文；不是只用夹具或复制既有结论。它们证明本次能找到阅读入口，不重新验证业务功能。

| 实际问题／查询词 | 找到并阅读的原文 | 使用意义与边界 |
|---|---|---|
| CLI 基础工程：`--task cli --query kernel-base`，另查 `--kernel-source` | [CLI 指南](../../../creator-docs/cli/OCLIVE_CLI_GUIDE.md) 的常用动作、首次准备与参数说明 | 可找到“在哪里生成、在哪里测试”的已有路径；不重新运行 Cargo 工程验收。 |
| 插件 RPC：`--task plugin --query plugin_rpc_invoke` | [DIRECTORY_PLUGINS](../../../creator-docs/plugin-and-architecture/DIRECTORY_PLUGINS.md) 的桥接与权限说明 | 返回入口后读到显式声明和本插件方法范围；命中不授予权限。 |
| 语音范围：`--task voice --query 平台` | [语音轨道](../../../human-docs/team/TRACK_VOICE_RECOGNITION.md) 的平台差异表及其未验边界 | 表中产品范围与实机证据分开阅读；不因导航成功把三平台语音转绿。 |
| Memory 开工：`--task memory --query retrieve` | [Memory 指引](../../../human-docs/modules/slots/memory.md) 的作者实现与消费者绑定步骤 | 找到真实调用案例与异步执行器限制；不把示例规则推广为公共强制义务。 |
| CI 所有权：`--query kernel-contracts` | [CI 路线文档](../../../creator-docs/roadmap/SOMEDAY_TOOLCHAIN_CI.md) 的历史首片和当前责任表 | 同一查询会返回历史及较新小节；日期、状态与覆盖仍由原文解释，不按路径排序裁决权威。 |

另用 `--task catalog --query 只覆盖` 定位本工具仍写“只覆盖八份”的旧说明，再实际更新使用文档。新查询 `--task catalog --query 即时原文导航` 找到新文字并报 `unstaged_change`、native 1；精选检查同样只指出本片改动的两个原入口未暂存。正常暂存、更新这两个精选版本后再复查，不让工具自动刷新哈希或签核。

一次没有命中的 `--memory-example` 查询保留为零结果，不将它杜撰为现有 CLI 参数；随后使用原文已有的 `--kernel-source` 完成参数查询。字面查询不是自然语言或同义词检索，任务筛选过窄时应去掉筛选或换词。

## 收口与未覆盖

本批属于 M 级可选阅读工具；不接既有门禁，不修改工作流、required gate、自动启动或必读规则。因此只跑 Node 定向测试与适用的文档／路径／登记／编码／债结构／差异检查，不跑 Rust、Dimension 5、模型或发行版回合，也不触发远端完整 CI。

实际使用目前只说明这些查询能帮助找到相关原文；没有对阅读时间、token 节省、全部文档正确性、AI 决策质量或运行能力作提升承诺。没有新增架构决策阻塞。达到“真实任务能定位、编辑能被发现、维护不再复制事实”后即停止扩展，后续随真实任务反馈再改进。

本地提交与冻结不自动合入原审计分支，也不表示远端已发布。历史报告与设计稿保持原字节；当前使用说明由 catalog README 拥有，避免每次使用再补一套报告。
