## 原因与决定

维护者确认卡片只承担导航／有来源摘要、缺失或过期可回原文；首批 6–8 份；核对记录只证明指定摘要与原文的一致性。此前 v0.2 的唯一入口、源码统一优先、全局 content_ok、字节阈值拆文及直接入 CI 路线不作为本片授权。

v0.3 本机设计稿 SHA256 为 `91A5D3B26D8109CD763520D19448EDEE0214438D1BCF1DB6868213D171CDE5C2`；本片交付的使用／维护方式以 [catalog README](../../catalog/README.md) 为准，不依赖接手人拥有本机 tmp 文件。

例如：查询“关系”会指向最小角色原文及其已有参考 Host 限制；修改文档但尚未提交时，工具显示 staged／unstaged 与版本失配，不会用旧哈希将新文字标为匹配。旧提交模式从同一提交读取记录与原文，不混用当前 working tree。

## 已实现范围

- 一份 [records.json](../../catalog/records.json)，八份原文、分项章节入口，一条最小角色限定摘要；不复制模块表、债务状态或规则正文。
- 一个 [ai-docs.mjs](../../../scripts/ai-docs.mjs) 入口，`query`／`check`／`boot` 只读输出。无新锁文件、人工序号、持久 BOOT、服务、npm 依赖或公开 SDK。
- 原文身份由 Git blob 提供；工作内容只归一 CRLF→LF 后与 index blob 比较，其余字符保持。工具禁 optional locks、fsmonitor、外部 diff／textconv、lazy fetch／replace objects，不刷新 index、不自动暂存／签署核对。
- 摘要核对绑定原文 OID 与条目摘要值；源／摘要／定位变化会使旧核对不可用。导航无摘要可用，文档匹配不代表代码仍支撑它。
- `handoff/README` 登记工具职责、AI 阅读索引增加可选链接，原规则保留；八份样本不是每轮必读清单。
