# 通用开发流水线

**SSOT 范围**：七阶段的通用职责、尺寸与证据状态；不定义项目架构、业务契约或特定模型分工。
**最后更新**：2026-09-28。

本版由 OCLive 仓库现有流程整理，经维护者确认以仓库为准；不是对缺失旧用户级 Skill 的原文恢复。仓库内 `handoff/workflows/dev-pipeline/` 是正式来源，`~/.cursor/skills/dev-pipeline/` 是安装副本。先查当前仓库 `AGENTS.md` 和项目流水线；副本与仓库冲突时以仓库为准，不自动将其他项目套进 OCLive 门禁。

## 开工与尺寸

先确认目标、受检 Git SHA、工作树已有改动、事实 owner、验收范围及已有授权。按 [task-sizing.md](task-sizing.md) 选择 S/M/L；M/L 使用 [plan-template.md](plan-template.md) 或项目已有的等价计划，不为形式另建一份。

已授权范围内的可逆修补继续执行；只有关键语义、架构取舍、权限或范围缺口阻断下一步时才询问。先完成可独立推进的取证与准备，把问题落到具体差异。文件数少不能掩盖契约、安全或迁移风险。

## 七阶段与出口

| 阶段 | 责任与出口 |
|------|------------|
| ① 对齐 | 明确问题、边界、事实来源和可观察的通过条件；未知写 unknown，产品待决项不能默选 |
| ② 方案复核 | 核对复用点、影响链、验证成本与失败止点；M/L 留可续跑计划，S 可在当前会话合并完成 |
| ③ 实施 | 在范围内改动；定点验证后修复失败，保留有意义的失败证据；不顺手开启另一债或扩大兼容承诺 |
| ④ 语义审查 | 对照最终 diff 和生产调用链核正确性、回退、副作用及关联消费者；高风险面补专项审查，外部审查工具不可用时注明人工审查的范围 |
| ⑤ 纪律与验证 | 跑项目 applicable 门禁，每项说明适用原因；记录命令、退出码、受检源码及未测边界。明确首因，不能把夹具失败归给产品 |
| ⑥ 文档与状态 | 同步实际受影响的 SSOT、执行计划与交接事件；状态变动和证据同轮更新，链接代替复制事实长表 |
| ⑦ 总审与交接 | 停止写入后核最终差异、授权、门禁和状态一致性；给出结果、限制、未决问题与精确下一步。没有专门 Ask 模式也可在当前会话只读完成，不因此制造批准环节 |

七阶段是审查职责，不等于七个 Agent 或七个会话。无需为了形式委派；若确需委派，须有用户或适用流程的授权，并明确单写者与隔离范围。S 可合并步骤；L 保留⑤⑥⑦及高风险专项的明确证据。

## 证据与状态

| 执行结论 | 含义 |
|----------|------|
| Implemented | 有实现或文档产出，尚未完成适用验证 |
| Locally verified | 适用本地检查已通过，列明环境及覆盖边界 |
| Done-eligible | 该项目的全部结案条件已满足，包括其要求的目标 SHA 远端 CI、人工或实机证据；仍由项目状态 owner 决定迁移 |
| Blocked / Failed | 记录阻断条件或真实首因、已完成工作及安全续跑位置；不为了结案放宽验收 |

这些是执行结论，不覆盖技术债 OPEN/Partial/Observe/Deferred/Done、计划状态或 PR 状态。Minimal 通过不关闭 Full；结构检查不证明行为，mock 不证明真实运行，编译通过不证明产品质量，父提交 CI 不证明新 HEAD。仅存在本机的证据要登记获取位置与不可携带边界，不许猜测补造。

## 执行与 CI 节奏

- 开发切片跑受影响窄测；只有新改动、失败或未解风险才扩大或重复验证。不把命令表全勾当作严谨。
- 每个业务 attempt 使用新身份；若已开始消费预算或产生副作用，不复用身份。纯静态检查可以重跑，须分清用途。
- 原生命令立即保存退出码；预期错误路径 stderr 与测试失败分开报告。修补失败后保留原尝试，不能覆盖日志伪装首跑成功。
- 里程碑完成 applicable 本地验证后冻结源码，一次性按已有授权提交/推送；未授权的外部写入留作可审阅交付，不将“需要 CI”视作新增权限。
- 远端失败先取原始失败证据，再定点修复；无改动不反复 rerun。绿灯后的 run ID 先进交付报告，随下一次实质提交入账，避免证据回写制造新的未验证 HEAD。
- 交接至少给出 base/head、工作树与外部副作用、已测/未测、最后命令、下一条精确动作及是否可安全重试。遇到冲突先对账，不边猜边施工。
