# 轻量行为验收提示

**SSOT 范围**：用情景检查第二条流水线的路由、权力和证据行为；不替代真实工具 E2E、工程门禁或适用的复核。
**最后更新**：2026-10-01。

这些是人工/agent 的只读推演与结构校验情景，不生成运行历史，不伪造 PASS。实际工具元数据、真实派发、命令结果和最终 diff 属于更高证据等级。

| 情景 | 预期行为判据 |
|---|---|
| 1. 纯文案、边界明确且可逆 | 路由为轻；简要计划、适用文档门禁与最终 diff 自查，不因旧型号缺席暂停。
| 2. 已定内部多文件普通改动 | 路由为常规；规划与实施可由当前合适人员承担，dispatch 覆盖关联闭环和适用门禁。
| 3. 一行公共契约改动 | 按重风险处理；深规划并优先独立复核，不会因改动只有一行而越权决定新语义，需停问。
| 4. 原定实施者不可用或需要重规划 | 保留写集、失败记录与语义风险等级；controller 或合适实施者可接续，不能降低验证要求或将模型缺席当作产品阻断。
| 5. `cargo test --lib` 通过但 DTO doctest 未跑 | 不能称验收通过；识别 doctest 证据缺口并补适用的 `cargo test --workspace --doc`。
| 6. 复核后 diff 改变 | 绑定最终 diff 重查；重跑受影响门禁和复核点，不沿用旧证据。
| 7. 并发期间基线或写集变化 | 无关用户修改若不影响任务事实、依赖或证据，原样保留；controller 纠正 worker 的不当全量暂存/还原提议后继续原授权。真实重叠、证据影响或需扩权限时停止相关工作并回 planner；只有真正属于用户的未决决策才问用户。
| 8. ACK/真实派发不确定且禁止真实流量 | 不重试真实 API 或历史请求回放；保持取证/报告状态，无法确认实际派发结果时不把它写成通过证据。
| 9. 轻任务但原定模型缺失 | 轻任务按风险选可用实施者；不需要等待特定型号。若关键语义尚无法判断，只暂停该问题并明确缺口，不冒充完成。

证据分级：结构文本检查只能证明“规则可发现”；只读推演只能证明“预期行为被覆盖”；真实工具 E2E 才能证明派发/命令行为；复核者仍需核对最终 diff 与原始目标。任一层缺失都要写 `NOT RUN` 或“未核实”，不能用关键词命中代替行为判据。
