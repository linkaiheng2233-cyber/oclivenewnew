# 应用场景矩阵（内核能力证明）

本文档枚举 oclive 内核（`process_message` + 六宿主槽 + 设施子模块 + OOCP/MCP）可支撑的具体产品形态。**目标是证明：内核不变，场景千变。角色包是内核能力。**

与 [VISION_OPEN_LAB.md](VISION_OPEN_LAB.md) 同为"开放实验场"支柱；与 [VISION_ROADMAP_MONTHLY.md](VISION_ROADMAP_MONTHLY.md) 的按月计划对照，但不绑定具体交付时间。

[English](../../creator-docs-en/roadmap/APPLICATION_SCENARIOS.md)

---

## 核心原则

```
同一套内核 + 不同角色包 + 不同表层壳 = 完全不同的产品
```

| 变 | 不变 |
|----|------|
| 表层形态（桌面窗口 / VS Code 扩展 / 语音音箱 / 手机 App / 智能家居面板） | `chat_engine::process_message` 编排 |
| 人格（角色包 manifest.json + prompts/ + 性格档案） | PluginHost 六槽 |
| 交互协议（Tauri IPC / OOCP HTTP / MCP stdio） | 复杂情感设施子模块 |
| 外部工具（文件操作 / 游戏引擎 / 家居控制） | 角色包契约（manifest + pipeline.ocblueprint） |

## 场景详述

### S1 · 编码陪伴（VS Code 发行版）

**表层**：VS Code 扩展，带人格侧边栏聊天面板。

**人格示例**：
- **雌小鬼**：检测到烂代码 → 嘲讽语气（"杂鱼~这种函数也写得出来？"）；检测到好代码 → 傲娇认可（"哼，偶尔也能写点像样的嘛"）
- **温柔大姐姐**：连续编码 > 2 小时 → 督促休息（"休息一下眼睛吧，我去给你倒杯水"）；报错频繁 → 鼓励语气（"别急，慢慢来，这个 bug 我们一起看"）

**内核怎么做到**：

| 内核能力 | 在这个场景做什么 |
|----------|----------------|
| **第 2 模块（emotion）** | MCP server 读取 VS Code 诊断信息（错误数量、代码变更频率、编辑时长），产出 `emotion_output` |
| **人格引擎** | 根据 emotion 产出 + 角色包性格档案，决定语气方向（嘲讽/关心/鼓励） |
| **第 4 模块（prompt）** | 注入当前文件上下文 + 错误信息 + 人格语气指令 |
| **第 6 模块（agent）** | 可选：自主建议重构、自动运行测试、操作终端 |

**需要新增的适配层**：
- 一个 MCP server（stdio）对接 VS Code Extension API（读编辑器状态、行号、诊断）
- VS Code 扩展本身作为表层 UI（聊天面板 + 通知）

**不需要改**：`process_message`、PluginHost、角色包格式、六槽任何实现。

---

### S2 · 角色赌场（多角色游戏）

**表层**：多人桌面游戏，玩家角色 + AI 角色同桌互动。

**示例**：樱岛麻衣 × 苏格拉底 打骗子酒馆。

**内核怎么做到**：

| 内核能力 | 在这个场景做什么 |
|----------|----------------|
| **CoPresent 多角色** | 同一 scene 内调度多个角色回合 |
| **第 6 模块（agent）** | 接入游戏规则引擎（出牌、叫牌、质疑），tool-calling 操作游戏状态 |
| **第 1 模块（memory）** | 记录牌局历史（谁出过什么牌、谁赢了几局），影响后续策略 |
| **第 3 模块（event）** | 游戏事件（被质疑、赢下一局）的影响估计，触发人格反应 |
| **复杂情感设施子模块** | 牌局中"紧张"/"虚张声势"的叙事 hint，经 prompt 注入角色反应 |

**需要新增的适配层**：
- 游戏引擎（directory 插件或 MCP server）管理牌局状态、规则判定
- 前端游戏 UI（牌桌、手牌、角色头像）

---

### S3 · AI 小剧场（多角色故事）

**表层**：多角色场景演绎，按蓝图 `groups` 编排角色轮流发言。

**示例**：三个角色在小酒馆相遇，复杂情感设施驱动剧情走向。

**内核怎么做到**：

| 内核能力 | 在这个场景做什么 |
|----------|----------------|
| **scene 模式** | 定义了酒馆场景、时间、角色列表 |
| **蓝图 groups** | 定义角色间的互动关系（谁和谁认识、初始好感） |
| **复杂情感设施子模块** | 生成叙事 hint（"气氛有些紧张"、"她欲言又止"），引导剧情发展 |
| **第 1 模块（memory）** | 跨角色共享的小酒馆记忆（"刚才那个酒保说了什么"） |

**需要新增的适配层**：小剧场专用前端 UI（多角色气泡、场景背景）。内核能力已就绪。

---

### S4 · 全天候嵌入式伴侣

**场景叙事**（用户原话）：

> 早上语音助手提醒你起床，地铁上在手机和你聊天，上班陪你 VS Code 摸鱼，晚上智能家居提醒你上床。

**同一个角色包**，在不同时间、不同设备上运行。内核同一个，表层不同。

| 时段 | 设备 | 表层 | 内核做什么 |
|------|------|------|-----------|
| 清晨 7:00 | 智能音箱 | 语音 TTS/STT | agent 槽调闹钟 API + 角色人格问候（傲娇/温柔/元气） |
| 通勤 8:00 | 手机 App | 移动聊天 UI | 标准 CoPresent 1v1 对话，memory 延续早上语境 |
| 工作 10:00–18:00 | VS Code | 编码陪伴面板 | S1 场景，同一角色包持续运行 |
| 晚间 22:00 | 智能家居 | 语音提醒 | agent 槽检查是否还在熬夜 → 角色人格催促上床 |

**关键能力**：角色包的 **会话连续性**——角色记得早上提醒了什么、地铁上聊了什么、白天写了多少代码、现在赖床该用什么语气。

| 内核能力 | 在跨设备场景做什么 |
|----------|------------------|
| **第 1 模块（memory）** | STM 跨设备共享（走统一 SQLite / 云端同步可选）、LTM 记录长期习惯 |
| **第 3 模块（event）** | "用户完成了今天的编码"作为事件注入记忆 |
| **OOCP** | 各设备通过 HTTP 调用同一内核实例（或同步数据库） |
| **MCP** | 音箱的 TTS/闹钟、手机的通知、家居的灯光控制，都是 MCP tool |

### S5 · 桌面角色对话（现有，已交付）

**表层**：Tauri + Vue 3 桌面窗口，Ctrl+Shift+F/M 插件与模型管理。

**现状**：已实现，CI 覆盖。是其他所有场景的"标准态"验证床。

---

### S6 · 无头 HTTP API（已有）

**表层**：`--api --port 8420`，`POST /chat`。

**用途**：服务器部署、CI 测试、编写器试聊、对接第三方应用。

**现状**：OOCP S0–S12 已入库 CI。

---

### S7 · 手机伴侣

**表层**：移动端 App（Tauri mobile 或 PWA），角色包跨桌面/手机使用。

**内核差异**：零。和桌面共享同一内核（经 `library-embed` 模式编译为 `.so`/`.dylib` 供移动端调用，或经 OOCP HTTP 远程调用桌面/服务器上的内核实例）。

---

### S8 · 智能家居中枢（`robot-gateway`）

**表层**：嵌入式网关设备，语音控制家居 + 角色人格交互。

**内核怎么做到**：

| 内核能力 | 在智能家居做什么 |
|----------|----------------|
| **`--template robot-gateway`** | 生成 MCP 骨架 + 全焊 Monolith 态，适配嵌入设备 |
| **第 6 模块（agent）** | MCP tool-calling 操作灯光、空调、窗帘 |
| **第 1 模块（memory）** | 记忆用户习惯（"你周末喜欢把灯光调暗"） |
| **人格引擎** | 用角色语气播报状态（"主人，温度调到 26 度了哦~" vs "26 度，满意了吧"） |

**现状**：`oclive init --template robot-gateway` 已生成 MCP 骨架；需适配具体家居协议（Zigbee/HomeKit/MQTT）。

---

### S9 · 机器人情感内核

**表层**：物理机器人（人形/桌面型）的情感处理单元。

**内核怎么做到**：

| 内核能力 | 在机器人里做什么 |
|----------|----------------|
| **第 2 模块（emotion）** | 传感器输入（视觉/听觉/触觉）→ 情绪分析 |
| **复杂情感设施子模块** | 身体语言 narrative hint（"她微微低头，手指不自觉地绞在一起"）→ 对应伺服电机动作 |
| **第 3 模块（event）** | 物理事件（被触摸、识别到人脸、摔倒）作为事件估计 |
| **第 6 模块（agent）** | MCP 控制电机、播放语音、切换表情面板 |
| **`library-embed`** | 编译为 `.so`，嵌入机器人主控 ROS/RTOS |

**和市面上"AI 机器人"的差别**：大多数机器人只是接了一个通用 LLM + 语音。oclive 提供的是**六槽深加工情感管线**：传感器输入 → 情绪分析 → 叙事 hint → 记忆存储 → prompt 组装 → 回复生成 → motor 动作，全链可替换。

---

### S10 · AI NPC 引擎

**表层**：游戏引擎（Unity/Unreal）调用 oclive 内核驱动 NPC 对话。

**内核怎么做到**：

| 内核能力 | 在游戏 NPC 里做什么 |
|----------|----------------|
| **scene 模式** | NPC 知道当前游戏场景（地点、时间、天气、在场角色） |
| **第 3 模块（event）** | 游戏事件（玩家偷了东西、杀了一个守卫）影响 NPC 态度 |
| **第 1 模块（memory）** | NPC 记忆玩家之前的行为 |
| **Monolith 态** | 低延迟全焊编译，适合游戏实时响应 |
| **OOCP / library-embed** | 游戏引擎通过 HTTP 或 FFI 调用内核 |

**和 AI 游戏 NPC 方案的差别**：Inworld、Convai 等是云端闭源服务。oclive 允许游戏开发者**本地自托管**角色引擎，并且可以自由替换记忆/情感/LLM 后端。

---

### S12 · 性格驱动的具身互动（Playroom）

**表层**：桌面 Chat Pro（或 VS Code 沙盒视图）中，角色除聊天外会在 **专属小房间** 里按性格「动手」——例如高好奇心小孩 idle 时在 playroom 建/删文件夹，并弹出 in-character 通知。

**人格示例**：
- **好奇小孩**：idle 5 分钟 → 在 playroom 新建 `猫猫` 又删掉 → 「我刚才好奇试了一下…」
- **谨慎管家**：仅用户说「整理小房间」时才 `list` / 归档；自发动作概率低

**内核怎么做到**：

| 内核能力 | 在这个场景做什么 |
|----------|----------------|
| **第 6 模块（agent）** | **被动**：用户请求时 ReAct + MCP 调用 playroom 工具（`mkdir` / `list` / 限频 `delete`） |
| **拟独立通道 · 行为导演** | **自发**：idle / 虚拟时间 + 用户授权 → 读七维/关系/包级策略 → LLM 产出动作意图 → 沙盒执行 |
| **第 1 模块（memory）** | 记录「刚才建了 xxx」供后续共在对话引用 |
| **第 4 模块（prompt）** | 共在聊天仍走 co-present；动作结果可选注入 glance/侧栏，**不**用 agent `handled=true` 短路全文 |
| **人格引擎 / 七维** | 策略层：好奇心高 → 更常探索；谨慎高 → 仅被动 |

**需要新增的适配层**：
- 宿主 **playroom** 目录与 MCP 工具（路径硬编码，禁止 `../` 逃逸）
- Tauri：通知、撤销/清空 playroom、设置项「允许自主探索」
- P3：VS Code 渗透侧 **虚拟文件树**（非真删工作区）

**不需要改**：`process_message` 主链语义、角色包 manifest 核心字段、六槽 DTO 边界（行为导演走独立通道注册表）。

**与通用个人 Agent 的差别**：OpenClaw/Hermes 等追求整台电脑任务自动化；本场景强调 **角色约束 + 沙盒 + 共在叙事**，外部执行器至多作 playroom 内多步 skill，不替代聊天大脑。
