## 3. 首支视频选题

**建议标题**：**《OCLive：从一个 Memory 模块开始，理解可组合的 AI 内核》**
**封面文字候选**：`六槽契约 · 一个实际调用`。
**长度目标**：约4分30秒。是成片剪辑目标，不承诺新机器能在这个时间内完成安装或编译。
**观众看完应能回答**：OCLive各层负责什么；模块实现、消费者绑定与断言改哪里；如何在自己的工程运行测试；结果通过意味着什么。

首片用“项目概念＋一个具体开发动作”建立信任。只展示Memory这个已验证案例，后续再用真实需求展开Host、发行版或其它槽位。

### 讲解边界

- 公共Kernel负责契约与硬边界；共享运行库/消费者在其外提供可复用接入支持；Host绑定资源并选择自己的运行流程；发行版负责产品体验。关系的唯一依据是[MODULE_MAP](../../handoff/MODULE_MAP_AND_HANDOFF.md#kernel-responsibilities)。
- 六槽接口与具体实现分开显示；不说六槽必须每轮全部执行，不要求所有Host采用参考Host或共享消费者。
- 示例只调用Memory，模型生成计数为0；不将字面匹配或窗口大小当作所有Memory实现的通用义务。
- 独立工程测试、消费者实际调用与目标Host场景验收分别说明；`doctor wiring`只展示声明，不能代替运行证据。
- 不使用未经本轮核实的竞品、专利或“全球唯一”论断；真实模型质量、真实TTS、全部平台/发行版、全部崩溃窗口和性能均不由首片转绿。

## 5. 录制排练卡

步骤以[SDK指南](../../examples/developer-sdk-memory/README.md)为准，不在脚本复制一套安装或生成配方。

1. 在**作者工程**执行`cargo check --locked`、`cargo test --locked`、`cargo run --locked`，保存三项binary测试与两条输出。
2. 按指南，只在作者工程的`main`和指定选取测试两个位置改`RecentLiteralMemory::new(2)`为`new(1)`；保留旧期望，运行指南中的具名测试并确认行为失败。
3. 按已确定的新承诺调整两处期望切片；保留其它断言，再test/run，确认`selected=1`。不要修改OCLive官方原件来准备镜头。
4. 如拍声明视图，按指南补可选元数据；旧CLI不认识命令时先核源码版本，不改Base。同步修改声明后再执行，仍标“declared、绑定未核实”。
5. 记录实际SHA、工具版本和命令结果；截图/录屏只采指定窗口。拍摄重试保留真实原因，不用编辑或字幕伪造成功输出。

首次安装、下载依赖及编译等待可剪辑，字幕写“构建等待已压缩”。文字中的运行输出是排练目标，不是本策划新产生的运行结果。
