# 技术亮点视频脚本：6 集短讲解

**用途**：把 [技术亮点](../architecture/TECHNICAL_HIGHLIGHTS.md) 里的机制拍成 6 集 3–6 分钟短片，用于项目宣传、开发者引流和路演前导。
**风格**：先给结果，再讲原理；每集只讲一个机制；不堆术语，不把“设计”说成“已交付”。
**配套**：每个机制的问题/做法/边界见 [TECHNICAL_HIGHLIGHTS.md](../architecture/TECHNICAL_HIGHLIGHTS.md)。

---

## 通用录制规范

- **画幅**：1920×1080，代码字号 ≥ 18；终端/浏览器缩放 125%。
- **节奏**：前 10 秒必须出现“结果画面”，不要先自我介绍。
- **字幕**：关键术语上屏（六槽、记忆三套存储、单写者、租约）。
- **诚实标注**：出现“实验/未上板/未生产化”时，画面角标同步标注。
- **片尾**：固定一句——“代码开源，欢迎自己换零件。”

---

## EP1 · 为什么一个 AI 角色需要内核（3–4 分钟）

**钩子**：我一开始只想做个桌宠，结果写了四次屎山。

| 时间 | 画面 | 口播 | 备注 |
|---|---|---|---|
| 0:00–0:20 | 桌宠成品：角色在桌面说话 | “这是一个 AI 桌宠。但真正难的不是让她说话，是让她**换一个模型、换一套记忆，还能继续活**。” | 先给结果 |
| 0:20–0:50 | 四次推翻时间线（Tauri 假象/上下文/拆分/费用） | “我推翻过四次：预览是假的、上下文越改越差、拆出来跑不了、一晚上烧掉几十块。” | 可用文字动画 |
| 0:50–1:30 | 白板画“内核 + 六槽” | “后来我想通一件事：我写的不是最好的，那就让它**方便抄**。把边界画清楚——内核只留契约，记忆、情绪、事件、Prompt、LLM、Agent 六个口都能拔插。” | 六槽逐个亮 |
| 1:30–2:30 | 代码：`process_message` → `slot_runner` | “一轮对话从 `process_message` 进来，按槽位解析、调用、合并、后处理。换 LLM 不动人设，换记忆不动主链。” | 只展示结构，不讲细节 |
| 2:30–3:10 | 桌面 + VS Code + 硬件三段画面 | “同一颗内核，可以跑桌面、跑编辑器、以后跑硬件。这就是我做它的原因。” | 片尾定格 |
| 3:10–3:30 | 仓库首页/开源协议 | “代码开源。你可以用整套，也可以只拿契约，做自己的 Host。” | 固定片尾 |

**不要讲**：15 个机制、专利、CI 细节。

## EP2 · 六个槽位：像 USB 一样换零件（5 分钟）

**钩子**：记忆、情绪、LLM 都能拔插——换一个，行为立刻变。

| 时间 | 画面 | 口播 | 备注 |
|---|---|---|---|
| 0:00–0:25 | 同一角色，先后用两个不同 LLM | “同一个角色，同一句人设，我只换了一个槽位——回复风格就变了。” | 先给对比 |
| 0:25–1:10 | 六槽图 | “六个槽：记忆、情绪、事件、Prompt、LLM、Agent。它们不是六个步骤，是六个**能力口**；可以全开，也可以只开 Prompt + LLM。” | 强调“可选” |
| 1:10–2:10 | 配置里把 `memory` 从 builtin 换成另一个实现 | “换记忆：检索策略变了，人设和主链没动。” | 展示配置 diff |
| 2:10–3:10 | 同一功能挂两个实例 | “一个口可以挂多个实现。问题来了：三份记忆召回，谁说了算？我们按槽位语义合并：状态类取最后、检索类取并集、生成类可竞速/回退。” | 对应 TECHNICAL_HIGHLIGHTS §1 |
| 3:10–4:10 | 关掉一个槽位（none） | “也可以显式关掉。但 Prompt/LLM 这种必需槽位，启动时就拦你，不让你运行期才炸。” | 展示启动报错 |
| 4:10–4:50 | 代码/目录结构 | “这些都在开源仓库里，接口、配置、测试都能查。” | 片尾 |

**不要讲**：合并代数的全部边界、插件授权细节。

## EP3 · 删掉聊天记录，她还记得你吗（4–5 分钟）

**钩子**：我把聊天记录全删了，她还在提上周的事。

| 时间 | 画面 | 口播 | 备注 |
|---|---|---|---|
| 0:00–0:25 | 删除聊天记录 → 角色仍提起旧事 | “聊天记录删了，记忆还在。因为它们是**两套存储**。” | 强对比 |
| 0:25–1:10 | 三张表/三块存储示意 | “聊天记录、短期记忆、长期记忆。编排只从后两者取；删聊天，不碰记忆。” | 对应 §5 |
| 1:10–2:00 | 记忆页/召回结果 | “长期记忆会衰减、会被提及强化；反复出现的记得更牢。” | 展示权重/提及次数 |
| 2:00–3:00 | 回放重建：从历史聊天重建记忆 | “换一个聊天后端，也能把历史回放成记忆——读路径可替换，写路径固定。” | 展示进度条 |
| 3:00–3:50 | 相似合并：两条相似记忆不重复膨胀 | “相似的不覆盖，只加提及计数；不引入向量库，端侧就能跑。” | 对应 §5 步骤 5 |
| 3:50–4:20 | 边界字幕 | “它不是语义理解，误报漏报都有；记忆质量仍取决于策略和模型。” | 诚实标注 |

**不要讲**：具体相似度公式（除非做开发者向加长版）。

## EP4 · 同一套代码，编译两次（4 分钟）

**钩子**：一份代码，两个二进制：一个能换零件，一个焊死。

| 时间 | 画面 | 口播 | 备注 |
|---|---|---|---|
| 0:00–0:25 | 两个二进制并排启动 | “左边是可插拔版，右边是焊接版。同一份功能逻辑，编译期把选定槽位焊成静态直调。” | 先给结果 |
| 0:25–1:15 | `monolith.toml` + `weld_modules` | “配置文件声明要焊哪些功能；脚手架从单一模板源生成静态实现，避免两份代码漂移。” | 对应 §2 |
| 1:15–2:10 | 构建日志/两个 target | “同一项目，两个可执行目标；开发用可插拔，量产后焊死降开销。” | 展示 target |
| 2:10–3:10 | 基准对比：启动/时延 | “到底省多少？用基准工具跑同一组输入，存历史对比。” | 必须用真实数字 |
| 3:10–3:40 | 硬件/嵌入式画面 | “这套是为硬件准备的：同一颗内核，换一个身体。” | 接 EP6 |
| 3:40–4:00 | 边界字幕 | “双构建态有维护成本；没有基准数据就不该默认开。” | 诚实 |

**不要讲**：具体优化百分比（除非当场跑）。

## EP5 · 桌面和 VS Code 同时开着，为什么不会打架（3–4 分钟）

**钩子**：两个宿主同时开，任务管理器里只有一个内核进程。

| 时间 | 画面 | 口播 | 备注 |
|---|---|---|---|
| 0:00–0:25 | 桌面 + VS Code 同时聊天 | “两个宿主，同一份记忆、同一个数据库，却没有互相覆盖。” | 先给结果 |
| 0:25–1:10 | 任务管理器：一个内核进程 | “因为只有一个**写者**。宿主不内嵌写库，统一走本机内核。” | 对应 §8 |
| 1:10–2:00 | 健康探测/附着/替换决策 | “附着还是替换，由一个纯决策函数判断：运行中内核、候选二进制、发行版画像、用户锁定。” | 画决策树 |
| 2:00–2:50 | 能力画像不匹配 → 替换 | “画像不匹配才替换；用户锁定优先；离线才派生内置回退。” | 展示日志 |
| 2:50–3:20 | 边界字幕 | “这是单机方案，不是多机协调；替换会中断当前会话。” | 诚实 |

## EP6 · 让角色活在硬件里（5–6 分钟）

**钩子**：同一颗内核，换一个身体——从屏幕到实体设备。

| 时间 | 画面 | 口播 | 备注 |
|---|---|---|---|
| 0:00–0:30 | 四季宝桌面模拟器：拿起/举起/放下 → 屏幕反馈 | “这是四季宝：角色能感知拿起、举起、放下，并在小屏上回应。” | 先给结果 |
| 0:30–1:20 | 感知 → 事件 → 角色回合链路图 | “感知内核只产事实；OCLive 只负责角色理解与表达；中间用类型化事件桥接。” | 对应 §12/§15 |
| 1:20–2:20 | 资源协调面板 | “LLM、TTS、屏幕渲染都抢 GPU/内存，所以有统一资源协调：租约、准入、可逆抢占。” | 对应 §3 |
| 2:20–3:20 | 桌面/VS Code/硬件三宿主 | “同一颗内核，桌面、编辑器、硬件三种身体。” | 对应 §8 |
| 3:20–4:20 | 实物板卡/结构件（若已到货） | “硬件还没 bring-up，这是下一步；现在跑通的是软件地基和桌面模拟。” | 必须诚实 |
| 4:20–5:00 | 片尾：仓库 + 招募 | “代码开源；欢迎 fork、换零件，或者做你自己的 Host。” | 固定片尾 |

**不要讲**：武器/火控相关表述；只讲娱乐、把玩、角色陪伴。
