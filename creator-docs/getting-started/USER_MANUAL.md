# oclive 用户操作手册

**SSOT 范围**：当前默认 Chat Pro 角色工作区的安装、聊天、设置、备份与自助排障；不定义角色包或插件契约。
**最后更新**：2026-10-27。
**适用界面**：启动进入角色库，选择或导入角色后进入它的运行空间。旧 Fluent / Tool 壳的菜单和实验功能不一定出现在这里。

[English](../../creator-docs-en/getting-started/USER_MANUAL.md) · [版本与内测状态](PROJECT_CURRENT_STATUS.md) · [错误码](ERROR_CODES.md)

## 1. 安装与首次启动

### 1.1 准备什么

| 项目 | 说明 |
|------|------|
| 安装包 | 使用与你的系统匹配的包。本轮候选安装包为 Windows x64；其他平台的源码或 CI 构建不等于已提供相同安装包。 |
| 模型 | 应用不捆绑 Ollama、llama-server、模型权重或 LoRA。聊天需要可用的本地模型服务或云端 API。 |
| 电脑与网络 | 本地模型的内存、显存和磁盘需求由模型与运行器决定；云端模型需要网络和服务商额度。 |

### 1.2 安装应用

1. 解压完整内测包，阅读随包说明；若提供 `tools/Verify-Package.cmd`，先运行校验。校验验证完整性，不等同于发布者身份认证。
2. 已有用户先关闭应用并备份，再运行安装器。不要手工混合新旧 `resources` 目录。
3. Windows 需要 WebView2。离线安装时若缺少它，先准备对应运行时，再按安装器提示重试。
4. 安装器若未签名，先核对来源与随包校验值。源码构建见 [CONTRIBUTING](../../CONTRIBUTING.md)，普通用户无需编译。

### 1.3 首次启动顺序

1. 在**角色库**选择角色或导入自己的角色包。
2. 进入角色运行空间，打开**模型与连接**，选择本地模型或云端 API，保存并检测连接。
3. 可以稍后配置模型；角色库仍可使用，但没有可用模型时不能生成正常回复。
4. 发送短消息并等待。保存成功只表示配置已写入，连接检测和真实聊天仍需分别确认。

### 1.4 如果本地模型不可达

确认运行器已启动、模型已下载，并核对地址与模型名。使用 Ollama 时可执行 `ollama list` 查看已有模型；应用安装完成不代表模型已安装。到**帮助与恢复**查看环境和内核状态，再按 [错误排查](ERROR_CODES.md) 处理。

## 2. 角色包管理

### 2.1 导入与升级

从角色库的**导入角色包**进入，按选择器提示选取支持的文件。核对来源；出现 ID 冲突或覆盖确认时，先确认对象。等待进度结束，不要强行关闭窗口。

安装版会把缺失的内置角色和插件补充到可写用户库，不覆盖已有同名包。升级后仍看到旧的自定义内容，不一定是安装失败；先导出、备份，再决定是否替换。

### 2.2 切换角色

返回角色库选择其他角色，进入它自己的运行空间。左侧缩略图使用现有立绘的局部裁切，运行空间保留完整形象；缺图时沿用已有回退。

### 2.3 为什么找不到市场

默认工作区不提供市场与分享安装入口。使用明确来源的角色包导入即可，不要照着旧版菜单寻找本轮没有开放的按钮。作者按需读 [创作流程](CREATOR_WORKFLOW.md) 与 [兼容性](../COMPATIBILITY.md)。

## 3. 日常对话

### 3.1 聊天与停止

主区域显示消息和输入框；生成中可停止。失败时先看简要原因，再展开技术详情。避免连续重发，以免重复消耗本地资源或外部服务额度。

### 3.2 快捷键

以应用内说明与**设置 → 高级设置 → 键位绑定**为准。入口受当前壳、角色和能力状态限制；旧版插件管理、调试面板或语音热键不是默认工作区可用入口的保证。

### 3.3 最近对话与记录

左侧显示当前角色自己的最近对话。同一角色可新建不同记录；查看、搜索、编辑或导出使用**设置 → 对话记录**。

**新建对话只分开聊天记录，角色记忆与关系继续延续。** 它不等于清空记忆或重置角色。旧场景记录也不会因剧情入口收起而被删除。开发者另查 [聊天与记忆边界](../../handoff/CHAT_STORAGE_ARCHITECTURE.md#transcript-only-conversations)。

### 3.4 身份、关系与表情

身份可在当前角色的身份控件或**设置 → 角色与身份**中选择；关系使用运行空间的关系控件。角色提供的选项与默认值仍适用，两者是不同设置，无需打开旧调试面板。没有身份目录的包不会凭空增加模板。

表情随回复和包内资源更新，缺图保留回退。独立表情提示不为选图额外调用一次模型；表现仍受模型遵循程度影响，不能只凭图片判断内部状态。

## 4. 设置、模型与数据

### 4.1 按分类查找

| 分类 / 入口 | 用途 |
|-------------|------|
| 外观与语言 | 语言、明暗与缩放；右上角可快速切换明暗，跟随系统仍在设置中选择。 |
| 聊天体验 | 现有输入、展示与聊天偏好。 |
| 角色与身份 | 角色包与当前角色支持的用户身份；关系在运行空间选择。 |
| 对话记录 | 查看、搜索、编辑、导出或按明确范围清理；清理前备份。 |
| 连接与修复 | 内核连接与恢复选项。 |
| 高级设置 | 现有高级偏好和键位，不表示全部旧实验功能重新开放。 |
| 帮助与恢复 | 内核/环境、最近报错与日志，手动复制或保存诊断。 |

Win98 彩蛋保留；启用时采用独立经典配色，关闭恢复默认外观。角色、草稿和模型配置不因换肤重置。

### 4.2 模型与连接

| 路线 | 配置与验证 |
|------|------------|
| 本地模型 | 独立准备运行器与模型，再按面板支持的方式选择或导入。Ollama 核对服务地址、模型列表与实际名称；GGUF/LoRA 还受运行器与模型兼容性限制。 |
| 云端 API / 自有兼容端点 | 按服务方提供的地址、模型 ID 和密钥填写，保存并检测。免费应用不代表外部服务免费；不要向维护者发送密钥。 |

云端“测试连接”使用已保存配置；修改地址、模型或密钥后须先保存。记录后端和模型 ID，先测试短消息。排错以当前角色实际生效的配置为准，不只看最后编辑的表单。

### 4.3 更新、备份与卸载

退出应用后，按应用显示的实际路径备份用户数据、角色库、插件配置和聊天存储；自定义过路径时也备份外部目录。**安装目录不等于用户数据目录**，只复制程序文件不足以保存聊天。

升级优先使用安装器；回滚使用对应旧版本与升级前备份，不假设旧版能读取新数据。卸载走系统应用入口，删除个人数据前另行确认。Chat Pro、角色包编写器和模型运行器是不同应用，不必一起卸载。

## 5. 常见问题与反馈

### 5.1 窗口空白或一直加载

界面已加载后，如果显示“这个区域暂时无法显示”，先展开并复制详情，或点“重新打开此区域”。主工作区的渲染异常保留左侧帮助与恢复入口；外层渲染异常有根恢复卡片。重试不会自动重发消息或清除聊天记录。诊断只保留在本次启动中，不依赖配置远程错误收集。

确认安装资源与 WebView2 完整，关闭后重启。若进不了主界面，使用随包修复工具并选择正确安装目录；不要直接删除整个用户目录。能进入界面时优先使用帮助与恢复。

### 5.2 一直思考、没有回复或模型报错

“已停止接收上一轮回复”只说明本地停止接收，不能保证服务端已停止生成。重新打开对话可查看已保存内容；不会因为这个提示自动重发同一消息。

核对后端、地址、模型名称与服务可达性，查看简要错误和详情；生成尚未结束时先停止，再决定是否重试。主运行器和回退服务同时失败时需要分别检查。

### 5.3 如何反馈

提供版本、系统、角色包/模型名称、时间、最小复现步骤、预期/实际结果和必要的脱敏日志片段。面板会遮蔽常见密钥格式，分享前仍需检查路径与正文；不要发送密钥、完整聊天数据库或整个用户目录。帮助与恢复不会自动上传日志。
